# Edge TTS 连接诊断（2026-09-29）

Pi5当前环境、实际Edge Xiaoxiao服务、现有mpg123及aplay，输出ALSA null，不发声、不启动AEC、不抢声卡；未停止用户App。16次请求，未复现120秒无声卡顿。

- 不含重试：新连接短句、15秒闲置短句成功；45/90秒闲置均报Cannot write to closing transport，此时websocket.closed仍False；每项之后的新连接长句全部成功。
- 含生产重试：20/30秒闲置直接成功；35/45秒闲置首次失败后重连成功，总合成时间分别1.579/1.102秒。四次新连接长句均成功。
- 新连接及短闲置时PCM正常到达，本批成功的首PCM约0.23～0.89秒（不含重连耗时）。null输出不等于扬声器实际延迟。
- 不能据少量样本声称固定30秒服务端寿命或排除网络。只能确认旧连接会失效，而closed检查不足；明确失败可由现有重试恢复，因此不足以解释之前全部120秒等待。
- Pi5 aiohttp 3.12.15源码确认：ws_connect默认ws_receive=None将HTTP协议read_timeout重置为None。因此ClientTimeout(sock_read=30)不能限制当前WebSocket收消息。外层future.result(timeout=120)仍是兜底。

本轮只加EDGE TRACE观测与独立诊断程序，没有修改正式预连接策略、超时、重试、AEC或睡眠逻辑。记录连接年龄、首消息/MP3/PCM、播放器写入、turn.end、每5秒的字节计数及清理。下次卡顿可直接区分服务无数据、解码无输出、播放阻塞或缺失结束标记。正式App需重启才能加载日志。

本机252项及10项子测试通过。JSON结果及逐阶段日志在同目录。测试副作用仅网络合成和null输出，所有诊断进程结束；未推送GitHub。
