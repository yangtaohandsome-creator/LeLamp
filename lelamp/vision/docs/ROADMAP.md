# 视觉功能开发路线

## 当前状态与目标

当前只完成文档准备，未进行环境准备、模型下载、程序编写或实机实验。模块边界见 [Vision README](../README.md)，下一步实验依据见 [摄像头选型验证](CAMERA_EVALUATION.md)。

小灯用于近距离桌面交互，人脸和手在画面中通常占比较大，偶尔多人入镜。目标能力包括人脸检测与跟随、静态手势控制，以及后续身份识别和动态手势。Pi5 只有 2GB 内存，视觉需与现有语音和 Pi Agent 共存，优先保障交互响应。

**第一阶段交付摄像头购买依据；第二阶段须等新摄像头到货并安装后，才细化正式设计。** 当前不决定购买型号、正式算法、接口字段、运行频率或资源预算。

## 阶段与交付条件

| 步骤 | 工作内容 | 完成条件 |
|---|---|---|
| 当前：规划准备 | 建立最小目录、职责和实验计划 | 文档链接有效，计划与已实现能力区分清楚 |
| 第一阶段 A：基础检查 | 核实现有 UGREEN 摄像头能力、桌面距离、视场和候选依赖可运行性 | 有真实设备参数和支持组合清单，安装兼容性问题有记录 |
| 第一阶段 B：独立验证 | 单独检测人脸、识别静态手势，组合运行并测 SFace 按需成本 | 有可复现配置、性能、识别效果和失败样例 |
| 第一阶段 C：选型结论 | 对比语音基线和并行负载，归纳瓶颈 | 输出最低需求、推荐参数、必需/可选特性及未验证项，支持后续购买决策 |
| 第二阶段 A：安装验收 | 新摄像头到货安装，核对方向、视场、近距成像和运动影响 | 满足购买需求；差异、线材牵制和活动范围限制已记录 |
| 第二阶段 B：正式设计 | 根据安装实测确定采集、模型、结果接口、频率与预算 | 完成正式实现计划和验收指标，再进入正式编码 |
| 第二阶段 C：逐步开发 | 基础感知 → 人脸机械跟踪 → 静态手势控制 → 身份识别与动态手势 | 每项分别通过离线、集成及实机验收，再扩展下一项 |

第一阶段可在后续实验任务中编写独立 benchmark，但不接入正式 app，也不发送视觉舵机命令。安装后的运动验证复用已有受控运动路径，不另开串口控制程序与 app 争用硬件。

## 候选能力与取舍

- **手势：**优先验证 MediaPipe Gesture Recognizer，观察 `Open_Palm`、`Closed_Fist`、`Thumb_Up`、`Thumb_Down`、`Victory`、`Pointing_Up` 等静态类别，保留 21 个关键点及可派生的手中心。使用视频或直播模式验证，不能只测逐张图片推理。
- **人脸检测：**优先验证 OpenCV YuNet，保留 bbox、中心、置信度及用于对齐的五个人脸关键点。先验证能否稳定看见目标，再讨论机械跟随。
- **身份：**按需验证 YuNet 检测、对齐、SFace 特征及相似度流程；单独测成本，不要求每帧运行。跟随人脸不以身份识别为前提。
- **动态手势：**后续优先评估约 0.5～1 秒的中心/关键点轨迹和简单规则，先不训练时序网络；实际窗口、方向定义和判定阈值等安装后确定。
- **暂不纳入基础路线：**Face Mesh、全身 Pose、MediaPipe Holistic、大型手势模型和连续 VLM 视频推理。物体检测等新增能力另按真实需求评估。

以上均为候选方向，性能或兼容性不满足时记录证据再调整，不能把候选库写成既定依赖。

## 正式设计时必须解决的问题

| 主题 | 约束及后续决策 |
|---|---|
| 帧与坐标 | 定义帧时间戳、图像尺寸、旋转/镜像、裁剪缩放及坐标转换；机械控制不得使用过期检测结果 |
| 采集与计算 | 单一采集源共享最新帧，避免旧帧积压；决定具体线程/任务方式及取消退出流程，不阻塞 app 语音协调 |
| 频率 | 采集、推理、舵机控制频率分别确定；20～30Hz 控制只是候选，不意味着低频检测产生了同等频率的新信息 |
| 目标选择 | 先关联并保持当前目标，定义丢失和重新选择；主人优先依赖身份能力，“最近交互对象”必须有可靠关联依据 |
| 跟踪控制 | 在 Motion 内评估比例控制、平滑和中心死区，再决定是否需要 PID；规定角度/速度限制、丢脸及结果过期行为 |
| 手势事件 | 区分逐帧识别和一次命令，设计稳定确认、解除后重新触发及冷却；定义未知类别和低置信度处理 |
| 摄像头自身运动 | 灯头移动会改变手的图像轨迹；优先考虑机械静止时识别动态手势、运动后清空历史，等安装后验证 |
| 身份管理 | 定义主人录入/删除、低质量拒识、陌生人判断及本地阈值验证；未经确认不持续保存人脸图片 |
| 语音关系 | 当前 `_motion_active()` 以 `current_motion_task` 是否结束判断运动；长期 tracking 会使播报期间持续走停止词分支。正式接入前决定接受该限制或在现有运动体系内补充实际运动状态，不另建占用系统 |
| 持续模式 | 复用运动锁、任务及取消标志；旧控制源实际停止后才能交接。临时动作后恢复有效 tracking，WORK_LIGHT 停止 tracking，sleep 统一结束跟踪；新指令不得被过期恢复覆盖 |
| 高层接口与网页 | 后续按需要定义跟踪启停、状态或场景查看能力；网页复用结果且预览按需开启，不在当前增加端点、视频流或网关 |

上述内容是后续正式计划的必答项，不是本次已实现接口。正式开发验收需覆盖运动独占、取消和模式恢复、手势误触发，以及语音交互回归；具体指标以选型与安装实测为依据。
