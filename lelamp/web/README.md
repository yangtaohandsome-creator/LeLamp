# 小灯局域网控制台

网站是现有 LampApp 的高层控制端，不运行第二个 app。控制页已增加视觉跟随按钮和只读状态；本次没有视频预览和网页标定。历史验收与当前验收分别记录在文末。

## 本机预览

```bash
uv run --no-sync -m lelamp.web --demo
```

访问 http://127.0.0.1:18793 。模拟 Agent、播报和机械设备，临时目录保存模拟数据，退出后删除。不会调用真实服务或改变用户录制动作。

实机部署后随 `python -m lelamp.app` 启动，入口为远程文本服务同一端口（默认 18791）的 `/`。当前 Pi Agent 新增请求轮次传递，部署需同时执行其 `npm run build`。Pi5 未安装 TypeScript 编译器，本次使用本机构建并测试通过的 dist。

## 页面

- 首页：软件状态、自检；软件记录不能证明扭矩和灯光物理效果。
- 对话：自然语言送入原 Agent，默认播报，显示是否播放/中断；浏览器持有自己的会话 ID，睡眠后重建。
- 控制：动作、30°转向/回正、办公照明高低/色调/亮度、待机和睡眠，以及人脸跟随、手部跟随、停止跟随。
- 管理：Timer、Alarm、Todo。修改闹钟采用先取消旧项，再填写新闹钟；取消成功后创建失败不会自动恢复旧项。
- 维护：动作录制、预览、follower/leader 分步校准和四种姿态保存。

## 边界与抢占

静态页面 → 同源网页 HTTP → LampApp → 现有 ToolExecutor/模块。页面不含 Token；同事 `/api/v1/agent/text` 的鉴权与请求格式不变。网站免登录，同网设备可以控制；仅接受同源浏览器请求，不开放 CORS。

网页控制停止旧推理、播报和运动；已成功执行的副作用不回滚。被中断的对话返回 interrupted。Pi Agent 的 turn_id 阻止旧请求晚到的工具继续执行；OpenClaw 回退未实现同等轮次传播，网页抢占目前以 Pi 后端验收。

Timer/Alarm 到期照常更新状态。统一队列暂停期间保留提醒；维护结束恢复后处理，已开始执行的到期动作不会因重新排队再执行一次。

## 维护步骤与恢复

1. 开始维护：停止语音采音，先沿现有睡眠流程收尾，再释放 app 串口。HTTP 保持运行。
2. 录制：准备 Leader → 开始采样 → 停止 → 命名保存 → 可选预览。默认禁止重名，明确勾选覆盖才允许替换，原 CSV 先备份。新动作不自动加入 Agent 清单。
3. 校准：选择 follower/leader → 手动置中 → 记录中位 → 开始范围采样 → 逐关节移动 → 停止 → 核对范围 → 确认保存。使用原校准格式与底层驱动，不调用终端交互命令。
4. 姿态：准备 Follower → 手动摆位 → 读取 → 选择睡眠/待机/高/低照明 → 保存。先备份 motion.conf，不改动作 CSV。
5. 确认结束维护后恢复语音。校准后须现场核对旧动作与姿态，不能认为旧录制自动兼容新校准。

备份位于原文件同目录的 `backups/`，带微秒时间戳。未保存校准退出时恢复原硬件校准；写入失败尝试恢复原文件和硬件，失败则保留维护状态及错误。页面提供恢复校准按钮；进程重启后仍可从备份人工恢复，不自动移动验证。

页面心跳每 5 秒发送，超过 15 秒无心跳停止采样/预览并释放设备，保持维护状态。重连后由操作者确认继续/结束，不自动上电。浏览器关闭也发送退出连接通知，但不能依赖浏览器一定送达，因此保留超时检查。

## 网页接口

- GET `/api/v1/web/state`、`health`、`items`、`maintenance`、`vision`
- POST `/api/v1/web/chat`：`text`、`session_id`
- POST `/api/v1/web/action`：`name`、`arguments`，服务端白名单限制
- POST `/api/v1/web/maintenance/{step}`：步骤专用参数；维护所有权通过 `X-LeLamp-Client` 标识

具体参数由 `api.py` 校验，与页面一起维护。不建议外部程序依赖维护接口；同事仍使用原有 Bearer 接口。

## 视觉跟随控制（2026-09-28）

控制页三个按钮复用 `start_face_tracking`、`start_hand_tracking`、`stop_tracking`，参数只能为 `{}`，经过原 `execute_web_action()` 与 `ToolSource.WEB`。开始请求成功只提示“请求已接受”，是否运行由后续真实状态决定。普通模式停止跟随结束 tracking 并回待机；照明中停止只锁定方向、恢复用户灯光并保留手势入口。关闭网页不会停止持续跟随。

- 办公照明中允许手部调向和停止，人脸开始仍要求先退出照明。调向规则见下节。
- 维护期间禁止三个操作，但可以查询状态。手部未标定时禁止手部开始，人脸跟随仍可使用。
- 从睡眠开启持续跟踪时同步更新机械唤醒标记，随后睡眠会正常停止运动、进入睡眠姿态并释放扭矩。
- 临时动作沿原仲裁取消并恢复一个持续任务；停止、睡眠、维护不恢复旧任务。

`GET /api/v1/web/vision` 返回 `{ok, vision}`，只投影现有 App 状态：视觉启停/错误/频率、有效检测人数和手数/手势、标定、跟随来源/阶段、运动任务运行状态、结果年龄。不会返回关节目标、模型、控制参数；读取不推进状态机、不打开摄像头、不访问舵机。

视觉面板可见时约每秒读取一次，同一时间只发出一个状态请求。切页、浏览器隐藏时暂停，返回立即刷新；请求超时或断线标记状态不可用，视觉停止或结果过期不展示旧手势。结果年龄标注为读取时数值，页面并非实时视频。模拟模式显式标注无硬件，手部开始约2.5秒后模拟进入跟随。

## 办公照明手势调向

`work_light` 使用独立 `WorkLightHandSession`，不复用普通跟随的退出手势状态机。进入默认白光/高姿态/75%后保持手势感知；显式暖光/低姿态仍有效。照明锁定下同手近距离张开→握拳开始调向，握拳→张开锁定；Tool 等待最多5秒选择近距离握拳手。调向不回tracking_home，仅控制既有base yaw/wrist pitch。

丢失立刻保持位置，5秒内重新确认握拳可恢复，张开不生效、不延长期限。超时进入锁定并清空旧手势，下次必须重新张开→握拳。调向和丢失暂停均显示用户当前亮度的30%，保持色温；只有锁定才恢复用户最新亮度/色温。调向期间的调亮、调暗、换色温修改的也是用户设置，不会被锁定恢复覆盖。

原手可见时不抢占。需要选手时使用0.3秒至少3个样本的掌骨尺度中位数，最大者至少为次大的1.5倍并持续确认后才选近手；相近多手不动。原手ID失效后5秒窗口内允许唯一/明显较近的握拳手重新接管，不要求近距离，不保证是原来的物理手。不会绕过近处不满足手势的手去选择远手。

网页新增“照明锁定、等待握拳手、手部调向、丢失暂停”及剩余时间、歧义提示，接口仍只读。停止调向保持照明，下一次新手势可启动。临时动作恢复调整后的照明位置并锁定；显式换姿态/朝向也锁定。睡眠、退出照明、维护清除会话。

高照明姿态现有pitch约99，超出跟随软限位95：保持照明时不移动；首次实际调向请求才按原速度/加速度平滑进入允许范围，再跟手。此过渡可因手丢失/锁定而取消，不直接发送99→95的跳变，也不放宽硬件约束。照明姿态改变后的响应矩阵仍复用原标定，实际跟随观感和光斑需现场验收。

配置在 `vision.conf`：`VISION_WORK_LIGHT_HAND_ENABLED=1`；设为0并重启恢复原照明流程。丢失窗口 `VISION_WORK_LIGHT_LOST_SECONDS=5`，尺度分离 `VISION_WORK_LIGHT_NEAREST_RATIO=1.5`。两项均只作用于照明，不改原跟随。没有网页视频和标定，不持久保存调向姿态。

### 2026-09-29 连续手势退出照明

照明复用当前普通跟随的纯退出序列判断（ExitGestureSequence），各自持有历史，普通跟随的状态转换保持不变。首次张开→握拳只启动；调向中同手3秒内握拳→张开→握拳→张开退出，锁定张开也可作为张开→握拳→张开的起点。第一次张开仅锁定，限时起点可用于近距离恢复调向；最终张开不新增距离限制。停止、丢失、超时、换手/多手歧义、临时动作清除未完成序列，丢失暂停的张开仍无效。

### 手势退出后的交流状态（2026-09-29）

手势退出办公照明现在依次收尾旧语音轮次、渐暗关灯、回待机，再恢复免唤醒监听。实际采音恢复后才显示监听灯，并重新获得 `voice.conf` 的完整 `CONVERSATION_IDLE_SECONDS`（默认15秒）。直接说话即可；无人说话满一个窗口才按原流程睡眠，不播放额外提示音或确认句。

仍有效的本地会话ID和已完成轮次保留；已结束会话重新建立。旧识别、Agent请求、未完成回答及对应动作资格取消，已经执行的Tool不回滚；Timer/Alarm通知保留。语音命令退出照明不取消自己的回答，播报后使用相同的完整窗口刷新规则。网页按钮及定时退出保持原行为，不额外激活语音。

睡眠、维护、新模式或网页接管会使未消费的恢复请求失效。恢复失败报告错误，不显示虚假的监听状态，也不自动重复移动。采音恢复异常时暂停语音并保留网页控制，修复后可通过已有恢复入口或重启App重试。真实麦克风、灯效及完整等待时间需要现场验收，自动化测试不能替代该验收。

### 照明中的感知与恢复等待优化

### 低开销网页检测预览（2026-09-29）

控制页新增“开启预览 / 关闭预览”，默认关闭，最高3 FPS，低分辨率画面按比例放大；不是高清监控视频，不提供录像或标定。开启仅查看已运行视觉，未启动/维护/异常/结果过期显示不可用，不会唤醒、启动跟随或改变照明。照明画面标明人脸检测停用。关闭浏览器只关闭预览，不停止跟随。

Vision发布已存在的model_image只读引用及同帧结果。Web单工作线程按需序列化BGR原始像素，无JPEG编码、缩放、重复推理或第二个摄像头；浏览器Canvas转换颜色并绘制同帧骨架、手势和目标框。原显示器预览接口保留。

GET /api/v1/web/vision/preview沿用同源限制，返回application/octet-stream：4字节大端JSON长度、UTF-8 JSON、width×height×3连续BGR字节。元数据只含尺寸/格式、序号、结果年龄、模拟标记、人脸检测开关、选中目标ID、人脸框和手部二维点/手势/置信度，不输出模型和舵机命令。响应Cache-Control禁止缓存；没有CORS。正常画面约230KB/帧，3 FPS约5.5Mbps，弱网会降低预览频率。

服务端最多一个传输/处理槽、一个序列化工作线程，所有页面共享3 FPS请求额度；忙碌429立即返回，不排队。停止、维护、模式/视觉代次/人脸策略变化后丢弃在途旧结果。浏览器单请求，1秒超时，连续失败3次暂停；切页或隐藏取消，返回按用户原选择恢复；旧画面到期清屏。预览异常不传播到控制流程。

性能边界：额外网络、内存复制和浏览器显示并非物理零开销。正式性能验收需要对比关闭/开启/关闭期间的推理、目标年龄、控制循环间隔及温度，特别是快速跟随；有可重复退化时降低预览频率复测，不能提高运动参数掩盖影响。

验收记录：本地/Pi5各243项回归和手机/桌面浏览器检查通过；15分钟Pi5隔离预览2640次请求成功，推理约10Hz、内存稳定。关闭后的对照负载发生变化，且没有真实快速机械跟随/正式App并发及局域网弱网测试，不能承诺零性能影响。预览默认关闭；详细原始指标和待验项见HANDOFF_VISION.md最新收尾记录。

### 预览闪烁修正

网页原先以采集后500ms清屏，与约334ms请求周期及网络耗时叠加，可能在正常两帧之间清空；429也会清空。现改为约380ms请求间隔、忙碌时500～700ms退避，仍单请求且不提高服务端3 FPS限额。短暂忙碌/失败保留最后一帧；估算画面年龄达到1秒标明过期，达到3秒清除。连续三次请求失败仍暂停，关闭、切页和已确认视觉停止/维护仍立即清屏。仅调整网页显示策略，不放宽机械控制的结果新鲜度，不改推理或跟随参数。

Chromium回归脚本 `tests/web_preview_browser.cjs` 配合无硬件demo运行，覆盖180ms网络延迟、间歇429不闪烁、持续忙碌时过期标记/清屏、恢复及关闭。运行示例：`NODE_PATH=/path/to/node_modules node tests/web_preview_browser.cjs`；默认demo地址18795，可用WEB_DEMO_URL覆盖。本次不需要重启App，刷新网页载入新JS；真人局域网观感仍由现场确认。

### 5 FPS预览试验

预览服务上限调整为5 FPS，浏览器使用220ms请求间隔（顺畅时约4.5 FPS，给限流留余量）；慢网自然降帧、单请求/单工作线程及过期策略保持不变。240×320 BGR在5 FPS上限下像素带宽约9.2 Mbps，不包括协议开销。只改变网页预览速率，不改变推理或运动频率。本地接口与浏览器测试不能替代Pi5并发运行的性能验收；服务端新限流必须在App下次启动后生效，旧进程仍是3 FPS。
